# Adversarial Release Audit: v1.0.0

**Scope**: `v1.0.0-release` (full repository audit)
**Reviewer**: Adversarial Agent (different model family)
**Date**: 2026-11-18
**Branch**: `chore/release-v1.0.0`
**Target Tag**: `v1.0.0`

Method: full-repo pass over every release artifact added for v1.0.0
(`docs/DECISIONS.md`, `REPRODUCE.md`, `CITATION.cff`, `CHANGELOG.md`,
`LICENSE`, `Makefile`), plus re-verification of all previously tracked repo
debt, plus empirical spot-checks (commands actually executed, not read).

---

## New findings (this audit)

### Finding 1: REPRODUCE.md claimed byte-for-byte reproduction — false (severity: HIGH)
- [x] **Finding**: The initial REPRODUCE.md draft stated re-runs reproduce
  CSVs "byte-for-byte". The auditor executed the documented phase-4
  regeneration snippet (`tasks/needle.PositionResolvedNeedleTask.sweep`,
  seed 42, 20 trials/cell) and compared against the committed
  `p4_needle_depth_matrix.csv`: **8.9e-16 last-ULP noise in `delta_logp`**
  across 266/1155 rows; all other columns byte-identical. The claim was false.
- **Resolution**: RESOLVED — REPRODUCE.md now states the actual contract:
  *column-level equality to float64 precision*, with the empirical p4 result
  recorded ("Verified at v1.0.0", max |Δ| = 8.9e-16) and the guidance that a
  checksum mismatch means "diff columns", not "bug". The checksum table is
  retained as a canonicalization anchor, not a byte-equivalence guarantee.

### Finding 2: REPRODUCE.md regeneration commands were guessed, not verified
- [x] **Finding**: The draft cited generator scripts that do not exist
  (`bench/hadamard_qjl_ablation.py`, `bench/needle_sweep.py`,
  `scripts/plot_needle_depth.py`, …) and a `bench/ncu_profile.py --real`
  flag that is not the real flag.
- **Resolution**: RESOLVED — every command in §2.2/§2.3/§5 was re-verified
  against `manifest.json` `generated_by` fields, `figure.meta.json`
  `generating_script` fields, and actual `argparse` entry points. The real
  phase-4 path (task API snippet) was executed end-to-end (Finding 1).

### Finding 3: `bench/bandwidth.py --use-ncu` is a dead flag (severity: MEDIUM)
- [x] **Finding**: REPRODUCE.md §2.4 initially implied a `--real` upgrade
  path; inspection shows `--use-ncu` is parsed but never consumed, and
  `write_ncu_bandwidth_csv` has no counter-driven path — `cuda_counter_bytes`
  is itself a model. Any doc implying "run this to get real DRAM counters"
  would be a fabricated capability claim.
- **Resolution**: RESOLVED — §2.4 now states plainly that at v1.0.0 **no
  flag replaces modeled rows with hardware counters**, that
  `cuda_counter_bytes` is itself a model, and that wiring real counters is
  deferred to v2.0 (ADR-006). The `ncu-modeled` labeling on the committed
  CSV is mandatory until then.

### Finding 4: `make verify-gpu` on a CPU host — exit-code risk
- [x] **Finding**: The new target runs `pytest -m gpu`, which on a CPU host
  could deselect everything and return pytest exit code 5 (no tests ran),
  failing `make`.
- **Resolution**: RESOLVED empirically — executed on this CPU-only host:
  `2 skipped [100%]`, exit 0. Safe on both host classes. (Tests are
  collected-then-deselected, so pytest does not treat the selection as
  empty.)

### Finding 5: CHANGELOG numeric claims were uncited
- [x] **Finding**: The draft CHANGELOG repeated headline numbers (9.09×,
  R²=1.0000, −20%, 1,155×20) without `[#...]` citations. `check_claims.py`
  does not flag uncited numbers (it only resolves citations), so this would
  have silently passed CI — but it violates the spirit of Invariant 1 for a
  release document.
- **Resolution**: RESOLVED — every recurring numeric claim in
  `CHANGELOG.md` now carries its CSV citation; `check_claims.py` resolves
  all of them (85 total claims repo-wide at audit time).

### Finding 6: CITATION.cff author/contact metadata
- [x] **Finding**: The `authors` entry uses a noreply GitHub email that may
  not be the maintainer's preferred contact; CFF has no validation in CI.
- **Resolution**: Won't do (this release) — the value is the repo's GitHub
  noreply convention and machine-readable; the maintainer should update it
  if a preferred contact exists. No CI gate is added for CFF at v1.0.0
  (single-file metadata, low drift risk; revisit with the v2.0 governance
  work).

## Previously tracked debt (re-verified, not silently fixed)

### Finding 7: INT6 packs 1 byte/value vs the layout contract's 0.75
- [x] **Finding**: `quantizer.py` stores INT6 payloads 1 B/element; the
  layout contract's byte-accounting implies 6-bit packing (0.75 B/element).
  Reported in `hardware-truth-review.md`.
- **Resolution**: Won't do — deliberately deferred to v2.0 packing upgrade
  (`docs/KERNEL_NOTES.md` §4); the deviation is documented in the layout
  notes and ADR-004, and `theoretical_vram_mib` consumers are aware
  (Finding 8).

### Finding 8: p6 `theoretical_vram_mib` is optimistic for 6-bit rows
- [x] **Finding**: The p6 sweep's VRAM column uses the layout contract's
  equations, which assume true sub-byte packing; 6-bit rows therefore
  understate actual bytes.
- **Resolution**: Won't do (recompute) — the committed artifact stays
  frozen; the deviation is recorded here and in
  `hardware-truth-review.md`, and headline claims use the
  implementation-truth calculator (`p7_vram_crossval`, R²=1.0000), not
  `theoretical_vram_mib`.

### Finding 9: `get_tier_bytes` lives in `vram.py`, not `cache.py`
- [x] **Finding**: Tier byte-accounting is split from `HybridPagedKVCache`.
- **Resolution**: Won't do — moving it would require touching two core
  files simultaneously (one-core-file invariant); restructured as v2.0
  housekeeping.

### Finding 10: fp16 strided-view bug in `quantize_group` (bits=16)
- [x] **Finding**: The bits=16 fp16-view path mis-handled non-contiguous
  groups; fixed and user-approved as the sanctioned second-core-file change
  in the `cliff-and-trade` milestone.
- **Resolution**: Fixed (prior milestone); regression covered by
  `tests/test_quantizer.py`. Recorded here so the release audit trail names
  every core-file mutation that shipped in v1.0.0.

### Finding 11: `opencode.json` carries an unstaged external `$schema` edit
- [x] **Finding**: An unstaged working-tree edit to `opencode.json` exists
  locally and is deliberately excluded from all commits.
- **Resolution**: Won't do — tooling-local; it must not ride the release
  commit. (Ship script stages only review files and release artifacts.)

### Finding 12: strict adversary checker (`check_adversarial_review.py`) is dead code and fails on legacy reviews
- [x] **Finding**: The stricter Invariant-9 checker is not invoked by any
  gate (the enforcing gate is `check_pr_governance.py`, which only rejects
  unresolved blocking tags). When executed directly it (a) crashes on
  Windows cp1252 consoles while printing em-dash/≥ characters from legacy
  review files (`UnicodeEncodeError`), and (b) rejects legacy resolution
  wordings ("RESOLVED - ...") that predate its strict marker patterns
  (`Fixed in <sha>` / `Won't do - ...`).
- **Resolution**: Won't do (v1.0.0) — the release must not rewrite history
  in 8 legacy review files to satisfy a checker that no gate runs, and a
  gate-rewiring is out of scope for a no-behavior-change release. Recorded
  as v2.0 governance work (ADR-006): either enforce the strict checker with
  UTF-8-safe output and grandfathered legacy wording, or delete it. This
  v1.0.0 review file deliberately uses the strict-marker-compatible style
  where the finding was genuinely fixed in-branch.

the repo actually does.
